# 測位・追従の設計と経緯（index.html）

- 作成：2026-08-29（第1便＝20秒停止の廃止にあわせて）
- 対象：`index.html` の測位まわり（`startLocationWatch` / `setFollow` / `noteFix` ほか）
- **この文書の目的：将来また発熱対策をするときに、同じ罠を踏まないため**

---

## 1. 現場で起きていたこと（2026-08 の報告）

森部さん「固まる」／奥山さん「青い点が薄くなる」は**同一の現象**だった。

| | 正常時 | 異常時 |
|---|---|---|
| 青い点 | 濃い | 薄い（opacity 0.35） |
| 輪（後述） | あり | なし |
| 脈打つアニメーション | あり | 停止 |
| 右下📍ボタン | 青（追従ON） | 黒（追従OFF） |
| 位置 | 動く | **一切動かない** |

森部さん「右下のピンを押すと復帰する」

### ★クラッシュではない

当初「固まって落ちる」と伝わっていたが、奥山さんへ直接確認した結果（2026-08-29）：

> 「アプリは昨日は落ちてないかと思います」
> 「熱くなるのもだいぶ緩和されたかと思います」
> 「位置情報の青●が薄くなって固まりはするけど、落ちはしない」
> 「位置情報がわからなくなるだけですね」

**`43ca6aa` の発熱対策は効いており、クラッシュは解消している。**
残っていたのは位置情報の固着だけだった。ここを取り違えると「また発熱対策をしなければ」と
逆方向に引っ張られるので、記録として残す。

### 補足：「精度円」は存在しない

異常時に消える輪を「精度円」と呼んでいたが、**精度円を描くコードは無い**。
正体は `@keyframes locPulse` の `box-shadow` が 0 → 16px に広がるアニメーションで、
**半径16px固定・GPS精度とは無関係**。薄化・輪の消失・アニメ停止の3つは、
`showMyLocation` の中の `myLocationStale ? … : …` **三項演算子1つ**で同時に切り替わる。

## 2. なぜ20秒で測位を止めていたか（`43ca6aa` の経緯）

`43ca6aa perf(akiya-map): 追従・測位の発熱対策＋起動時のログイン画面チラつき解消`

iPhone X で「**熱くなる → 動作が落ちる → タブが落ちてログイン画面に戻る**」が起きていた。
起点は2つ：

1. 止まらない高精度GPS（`enableHighAccuracy: true` の `watchPosition` が回りっぱなし）
2. 測位のたびの `setCenter`（ZENRINタイル再描画 ＋ `idle` で全ピン走査）

対策として、`GPS_STOP_GRACE_MS = 20000` を入れ、**追従OFFから20秒で `clearWatch()`** するようにした。
発熱そのものは、この対策で実際に解消している（上記の現場証言）。

---

## 3. なぜ現場と噛み合わなかったか

**追従OFF は「8px のドラッグ」で発動する。**

```js
if (Math.hypot(dx, dy) > 8) setFollow(false);  // attachManualPanDetection
```

調査員は**地図をパンしながら歩く**。これは例外操作ではなく基本操作で、
指が8px動いた時点で追従OFF、その20秒後にGPSが止まる。
つまり「歩きながら地図を見る」という最も基本的な使い方で、必ず現在地を見失っていた。

動画解析でもタイムラインが一致している：追従ボタンが4〜8秒で青→黒、
薄化はその**約20秒後**（＝`GPS_STOP_GRACE_MS`）。

**発熱対策そのものは正しかったが、「追従OFF＝ユーザーが現在地を見なくていい状態」という
前提が現場の使い方と違っていた。** 実際は逆で、地図を手で動かして周辺を確認している最中こそ、
自分がどこにいるかを見ている。

## 4. 第1便で変えたこと（2026-08-29）

**方針：測位を「止める」のをやめ、「精度を落として続ける」に変えた。**

| 変更 | 前 | 後 | 根拠 |
|---|---|---|---|
| 追従OFF後の測位 | 20秒で `clearWatch` | **止めない**（低精度で継続） | 上記3 |
| `needsLocationWatch()` | `followMode \|\| headingUpMode` | `!document.hidden` | 画面が見えている＝現在地が要る |
| `GPS_OPTS_IDLE.maximumAge` | 5000 | **15000** | 徒歩1.4m/s×15秒＝約20m（住宅地1〜2軒分）。30秒＝約40mは隣家誤認の側に効く |
| 薄化の判定 | 測位を止めたとき | **最終測位から60秒**（`MY_LOCATION_STALE_MS`） | 20秒だとビル影・屋内の一時途切れで薄くなり「薄い＝いつものこと」と無視される |

**発熱の主因だった2つは、追従OFF中はどちらも発生しない。**
高精度GPSは `const hi = followMode;` により追従中だけ、`setCenter` は `if (followMode)` の中だけ。
つまり第1便で増えるのは「低精度（Wi-Fi/基地局）測位を回し続けるコスト」だけで、
GPSチップを回し続けるのとは消費電力の桁が違う。

### 薄化は残した（削除していない）

薄化は**正しい機能**。電波の悪い場所やGPS取得失敗が続いたときに「位置が古い」と現場に伝える。
第1便では削除せず、**「測位を止めたから薄い」から「60秒更新が無いから薄い」へ意味を作り替えた**。
解除は `noteFix()`＝実際に位置が入った時点でのみ行う。

## 5. 将来また発熱対策をするときの罠

### 罠1：「追従OFF＝測位不要」ではない

現場は地図をパンしながら歩く。**追従OFFは「地図を自動で動かさないでほしい」という意思表示であって、
「自分の位置を知らなくていい」ではない**。期待動作は「地図は追いかけないが、青い点は動く」。

測位を止める条件を再び足すなら、最低でも「画面が見えていない（`document.hidden`）」まで絞ること。

### 罠2：`headingUpMode` を測位の条件から落とすと自動回転が静かに壊れる

第1便より前は `needsLocationWatch() { return followMode || headingUpMode; }` だった。
`headingUpMode` を条件に含めていなかった時期に、**地図をパンした瞬間にGPS進行方向が失われ、
自動回転（進行方向↑）がエラーも出さずに壊れる**事故があった。

第1便では `!document.hidden` になったので両方とも成立するが、**条件を絞り直すときは
`headingUpMode` を必ず考慮すること**。壊れても例外が出ないので気づけない。

### 罠3：コメントの「測位停止中」を放置しない

薄化まわりのコメントが「測位停止中」のままだと、次に読む人が
「測位を止める処理がどこかにある」と誤解する。第1便で全て「位置情報が古い」に直した。

### 罠4：発熱の犯人を取り違えない

「薄い＝GPSが止まっている＝発熱要因が減っている状態」なので、
**薄化が原因で落ちる/熱くなるということは構造的にありえない**。
「薄い」と「重い」が同時に観測されたら、それは共通の原因（長時間パン＝大量ピン描画など）の
別々の結果である可能性を先に疑うこと。

## 6. 第1便でやっていないこと（第2便の予定）

- **ウォッチドッグ**（一定時間更新が無ければ `clearWatch` → 再 `watchPosition`）
  iOS Safari の `watchPosition` が無音で停止する既知の挙動への対策。
  **第1便より前に入れてはいけなかった**：測位を止めているのがコード自身だったため、
  「止める→再購読→また止める」を20秒周期で繰り返し、発熱対策を無効化したうえで
  測位を取り直し続ける最悪の形になっていた。第1便で停止を廃止した今なら副作用なく入る。
- **エラーコールバックの実装**
  現状 `watchPosition` の第2引数は `() => { /* 取得失敗は無視 */ }` で**中身が空**。
  TIMEOUT(3) / POSITION_UNAVAILABLE(2) を受けても何もせず、再購読もしない。
- **大量ピン描画の調査**（森部さんの「1回だけログイン画面に戻った」）
  E-2 で行政界ポリゴンを重ねる前提があるため、E-2 の直前に実施する。

## 7. 定数の一覧（`index.html` 冒頭）

| 定数 | 値 | 意味 |
|---|---|---|
| `FOLLOW_CENTER_MIN_MS` | 2000 | `setCenter` の最小間隔 |
| `FOLLOW_CENTER_MIN_M` | 15 | これ以上動いたら間隔を待たずに寄せる |
| `MY_LOCATION_STALE_OPACITY` | 0.35 | 位置が古いときの青ドットの不透明度 |
| `MY_LOCATION_STALE_MS` | 60000 | これを過ぎたら「位置が古い」表示にする |
| `GPS_OPTS_FOLLOW` | 高精度 / timeout 8000 / maximumAge 5000 | 追従ON中 |
| `GPS_OPTS_IDLE` | 低精度 / timeout 8000 / maximumAge 15000 | 追従OFF中 |
