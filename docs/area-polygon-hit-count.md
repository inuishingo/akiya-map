# 取込対象市区町村の 大字(OAZ) 件数 実測

- 実施日：2026-08-28
- 目的：E-1（行政界ポリゴン取込）の `areaPolygon` プロキシは `limit=0,1000` の**1回取得**で設計している。
  1000件を超える市区町村が実在するなら分割取得（オフセット送り）の実装が要るため、事前に実測した。
- 方式：[scripts/probe-oaz-hit-count.js](../scripts/probe-oaz-hit-count.js)。Functions を経由しない直叩き。
  `address_polygon=false` ＋ `limit=0,1` で `info.hit`（総件数）だけを取る＝**1市区町村あたり1リクエスト**。直列・各300ms待機。

```
GET /search/address?address_code=<JIS5桁>&code_match_type=2
    &address_level=OAZ&address_polygon=false&datum=JGD&limit=0,1
```

## 結論

**1000件を超える市区町村は0件。** 分割取得の実装は E-1 に含めなくてよい。

ただし最大の **岐阜市(21201) は848件**で、上限1000に対する余裕は152件（15%）しかない。
将来 AZC（字丁目）レベルまで対象を広げる段階では確実に1000を超える（緑区のAZCだけで423件の実績）ため、
**分割取得は「AZC対応時に必ず必要になるもの」として据え置き**、E-1（OAZのみ）では実装しない、が妥当。

## 付随して見えたリスク（件数とは別件）

取得**時間**は件数にほぼ比例する。緑区105件＝**5.4〜6.0秒**の実測から線形に外挿すると、
岐阜市848件では **40〜50秒**かかる見込み。当初のタイムアウト設定ではマージンが5秒しかなかったため、
**この調査結果を受けて `areaPolygon` のタイムアウトを引き上げた**（関数300秒／上流の自前打ち切り280秒）。
上限いっぱいの1000件（約1分）を引いても構造的に当たらない。

- 打ち切りに当たった場合は 504 `upstream_timeout` を**JSONで**返す設計なので、無言の失敗にはならない。
- 岐阜市の取得時間そのものは実測していない（本調査は1市区町村1リクエストの制約下のため）。
- もし将来それでも間に合わないなら、対処は「分割取得」＝AZC対応時と同じ実装で解決できる。
