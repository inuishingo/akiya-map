# E-2 への申し送り（E-1 運用で出た積み残し）

- 起票：2026-08-29（E-1 の本番デプロイ・緑区取込の直後）
- E-1 では直さない。E-2（周回機能をエリア＝大字ベースに載せ替える段）で対応する。

## B-1. 市区町村セレクトに「まだピンの無いエリア」が出ない

### 症状

`🗾 行政界取込` モーダルの市区町村セレクトに、**ピンが1件も無い市区町村が候補として出ない**。
今回の名古屋市緑区(23114)がまさにこれで、セレクトから選べず**直接入力で回避**した。

### 原因

`admin.html` の `openAreaPolyModal`（`// エリアDD：ピンが存在する areaCode を areaName で列挙。` のブロック）で、
候補を `allPins` から作っている。

```js
const nameByCode = {};
allPins.forEach(p => { const c = areaKey(p); if (c) nameByCode[c] = p.areaName || c; });
```

「既に調査したエリア」しか出ない作りになっている。

### なぜ直すべきか

行政界ポリゴンの取込は、**これから調査するエリアを先に用意する**使い方が主になる。
「ピンがある＝もう調査済み」のエリアだけ選べるのは、想定している運用と逆。

### あるべき姿

対象6府県（**愛知・岐阜・三重・京都・滋賀・奈良**）の市区町村を全件出す。

### 着手時に使える素材と注意点

**素材**：`scripts/muni_master.json`（総務省 全国地方公共団体コード・1,916件）に必要な情報が揃っている。

```json
{ "code": "23114", "name": "名古屋市緑区", "pref": "愛知県" }
```

対象6府県の内訳（実測）：

| 府県 | 件数 |
|---|---|
| 愛知県 | 70 |
| 岐阜県 | 42 |
| 京都府 | 37 |
| 奈良県 | 39 |
| 三重県 | 29 |
| 滋賀県 | 19 |
| **合計** | **236**（うち政令市の親コード2件を除くと **234**） |

**注意1：政令市の親コードを候補に入れないこと**
`23100 名古屋市` と `26100 京都市` の2件は区を持つ親レコード。
`areaPolygon` は `address_code` の**前方一致**（`code_match_type=2`）で引くため、`23100` を投げると
名古屋市16区の大字を全部引いてしまい、`AREAPOLY_HIT_LIMIT`(1000件) に当たって止まる可能性が高い。
**候補から除外する**か、選んだら区に展開する。

**注意2：`muni_master.json` をそのままアプリから読まないこと**
このファイルの `_note` に「アプリ(index/admin)からは読み込まない」と明記されている
（areaCode バックフィル移行専用）。133KB を admin.html が毎回読むのも無駄。
**6府県分だけ抽出した定数（236件・約10KB）を admin.html に埋め込む**のが素直。
抽出は使い捨てスクリプトでよい。

**注意3：件数上限の再確認が要る**
`docs/area-polygon-hit-count.md` で hit を実測したのは、当時ピンがあった**21市区町村**だけ
（最大は岐阜市848件）。234件に広げると **1000件超の市区町村が出る可能性**がある。
E-2 着手時に `?count=1`（ポリゴンなし・1件0.1秒）で234件分の hit を先に測り、
上限超えがあるなら分割取得の要否を判断すること。

### 回避策（E-2 まで）

モーダルのセレクトで「（直接入力する）」を選び、JIS5桁を直接入力する。
今回の緑区取込はこれで問題なく通っている。
